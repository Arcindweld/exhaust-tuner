# Field-edit speed, 2026-11-18

Every keystroke in a field re-renders the active tab. Before this work the tab's whole HTML was rebuilt and written
with `innerHTML`, so the browser styled and laid out the whole tab again, and the Hangers tab spent most of its time in
one isolator search. Aim: halve the median field-edit time on the three heaviest tabs (Hangers, the boosted Intake tab,
Mufflers) without changing a displayed value, and never show a result that does not belong to the inputs on screen.

Result in short: **Hangers −57 % and Mufflers −66 % (goal met); boosted Intake −31 to −42 % depending on the run (goal
missed by about 8 to 19 points; see "What remains slow").** The guard (`web/tests/incremental_ui.js`) finds no
difference between the page writing in place and the page writing in full, over every panel's text, HTML and field
states. Same hard rules as the UI passes: no calculation, default, input id, project key, URL hash, bridge or host
contract changed; no external resource; no pinned number changed.

## How it was measured

- `tools/perf/bench.js`: the same protocol as `web/tests/ui_ui.js`'s `timeEdits` (1440 px, Liberation Sans forced on both
  pages, synchronous input event to forced layout, median of 15 edits), best of 3 runs, old and new pages **interleaved**
  tab by tab (this container's speed drifts by 10 to 20 % over minutes; numbers taken at different times do not
  compare). Fields: Hangers `hg-od` (×1.01 and back), Intake `i-hp` 440/450 after K24A2 + Turbocharged (the ui_ui
  journey), Mufflers `m-f` (×1.01 and back), 4-Stroke `f-rpm`, Headers `h-rpm`, Sound `s-red` (6400/6500).
  `FRESH=1`: a value never used before on each edit (as typing a new number), so nothing kept from an earlier
  render can be reused; `throttle 4`: CDP `Emulation.setCPUThrottlingRate` 4, standing in for a slower shop PC.
- `tools/perf/prof.js`: the same edits with timers round the page's own functions (a debug hook injected into the
  page as served from memory; the file is not changed), the DOM writes, and every layout read (`offsetWidth`,
  `clientWidth`, `getBoundingClientRect`, …) with its stack: the forced synchronous layouts. The timers add 5 to 15 %.
  `tools/perf/trace.js` (devtools timeline: style, layout, parse), `agg.js` (CPU profiles by function),
  `churn.js` / `morphstat.js` (what changes between two renders / what the patch replaced), `morphbench.js`,
  `load.js` (first load, tab switches), `abcompare.js` (old page against new page, same seeded edits, every panel's
  HTML compared).

## What was cut, the gain, and why it cannot show a different or stale result

1. **Hangers geometry and fin, same arithmetic** (Hangers 194 → 99 ms on its own). `hgScan`: each outline edge is
   placed once on the scan lines it spans (y in [lower end, upper end), by binary search on the line heights) instead
   of being tested on every line; per line the same edges are visited in the same order with the same expression, so
   the same numbers (an outline with a NaN height falls back to testing every edge). `HG.sample`, `minD` and
   `HG.simple` write out `add/mul/sub/pol` and `segX` inline: the same operations in the same order, no temporary
   arrays. `filletForWaist`'s 80-step bisection stops once the midpoint equals an end: from there the state cannot
   change (gap(hi) ≥ 0 and gap(lo) not, by construction) and the remaining steps would repeat it, so the returned
   radius is the same. `hgFin`: the conduction terms and spacings that do not change between passes are worked out
   once by the same expressions; sums, maxima (a `Math.max` fold, NaN included) and the sweeps keep their order.
   `reachFor`'s part-and-temperature evaluations are kept for the render (key: the inputs object, of which only the
   reach varies; the searches for the isolators share their first steps). Checked: `abcompare.js` old against new,
   Hangers, seeds 1 to 3, 220 seeded edits (every part type reached), every panel's HTML identical.
2. **`setHTML`: a render's HTML written in place** (the main cut for Intake and Mufflers; replaces `innerHTML` for the
   results of Intake, Mufflers, Hangers, the Mounts designer, Headers and Crossover). The HTML is parsed into a
   template and compared node by node with the template written last time (kept beside the page, untouched): a node
   whose HTML is the same keeps its node in the page; a changed text is set; changed attributes are set; anything whose
   children differ in number or kind is replaced, as are fields (inputs, text areas, multiple lists), drawings (svg,
   canvas) and run status lines; a drop-down list is kept and its choice set as a newly parsed one makes it (the last
   option marked selected, else the first not disabled). Same HTML as last time: nothing is parsed; only the drawings
   and fields are made afresh. Why the page ends as a full write would leave it:
   - the display passes (folding, number columns, stacked-table labels, "do this" buttons, quieter units, sections
     list) now set **and clear** what they add, so a kept node ends as a new one would: `tblPolish` sets or clears
     `num` on every cell (it only added it; a table that turned unpolishable or a row with a `colspan` kept stale
     classes), clears `data-l` and `stk` where they no longer apply; `foldPass` removes `data-st` when a section is fine
     and gives a section a new id when its key changed (the ids it gives follow `data-sec`); `fixPass` rewrites its
     button when the label changed; `addToc` and `foldPass`'s list update the list in place; their changes are marked
     as the page's own;
   - anything else that changes the written nodes after the write (a button's message, a section folded by hand, a
     render's own direct write) is recorded by a MutationObserver and that node is written afresh next time;
   - a folded section kept from before that holds a drawing is opened while the render draws, then folded again by
     the fold pass: the drawing is laid out to the width of an open section, as in a newly written one (found by the
     guard: 754 against 756 px);
   - a hidden tab's nodes are left as a full write leaves them (undecorated): when they were decorated while shown,
     the next write while hidden is in full;
   - an error while patching writes the whole thing.
   Gain: Intake setHTML 13 ms (parse 5 to 7 of it) against innerHTML 12 to 15 plus 40 ms of forced layout; layout now
   about 16 ms. Mufflers' forced layout 14.5 → 2.6 ms. Off-tab producers: identical HTML skips the write entirely.
3. **Kept results with complete keys.** Mufflers: the packed can (`absorbKept`, last six cans) and its loss at each
   whole hertz; the key is everything `calcAbsorb` reads, its inputs and the exhaust gas in use (`EXH_GAS`, which a fuel
   changes), written by `numKey` (which tells NaN, null, −0 and ±Infinity apart). Mufflers 47 → 26 ms in an
   interleaved run for an edit that does not change the can; an edit of the can's own fields gets none of this.
   Intake: the cooling of each pipe in the exhaust march (`XC_KEEP`, last 48), key the pipe, flow, cooling inputs and
   `EXH_GAS`; the profile is handed out as a copy. Within a render 5 of 13 marches repeat a pipe.
4. **Drawings on hidden tabs**: `widthOf` returns 328 for a figure inside `[hidden]` (display:none!important, so its
   width read 0 and gave 328) without laying the page out.
5. **Tab strip**: `tabIntoView` reads the strip after the render, not before it (it laid the page out once more).

Checked by `abcompare.js` against the page before (Mufflers seeds 1, 4, 9; Intake K24 seeds 1, 5; Hangers 1 to 3;
Headers 9; 30 to 80 edits each): every panel's HTML identical after each edit.

## The differential guard

`web/tests/incremental_ui.js` (about 2 min 40 s here): two pages in lockstep, each in its own browser context: A the
page as it is, B the same page with `window.__fullWrites` set before load (every write the plain `innerHTML` it was
before, and nothing kept between renders: `absorbKept` and `XC_KEEP` bypassed, so the keys are tested too). A turbo
build (K24A2, Turbocharged), then 260 seeded actions (seed 7), 72 % on the three heavy tabs: field changes as a user
would make them (staleness_lib's `change`: in the units shown, a list to another option, sometimes blanked), sections
folded or opened by hand, Expand all / Collapse all, the unit toggle, Simple/Expert, "Use" buttons, engine presets,
looks at another tab. After each action both settle and run their idle passes; every panel's (all 13, hidden ones
too) and the vehicle bar's textContent, innerHTML and field states (value, checked, chosen option) must be identical.
No ids are generated per render, so nothing is normalised. It also checks A really wrote in place (patched and
unchanged writes counted). Final code: 250 checks, no difference; A wrote 148 times patched, 1,027 unchanged, 80 in full.
Seeds 3 and 11 (150 actions each) also pass. `tools/validation/incremental_sweep.js seeds=1-10 n=400` runs it longer.

Found by the guard and fixed before it passed (each a case where a kept node would have differed from a new one):
the fold pass's section id after the section's key changed; a drawing in a folded kept section drawn 2 px narrow;
`data-st=""` left on a section that turned fine; and, against the old page, `class=""` and stale `num` classes after a
table changed shape.

Found by `staleness_ui.js` in the first full-suite run (its project inventory probes every select): the sections
list's "Jump to" select, in a list kept from the render before, kept the section picked where a new list starts at
"Jump to…". A kept list now starts unmarked and unpicked, as a new one does (the section in view is marked again by
its IntersectionObserver). The row's sideways scroll in a kept list is not reset (reading it would force a layout); the
marking scrolls it to the section in view either way.

## Tried and reverted

- `content-visibility:auto` on the sections: Intake 94 → 43 ms and Mufflers 61 → 41, but `innerText` leaves out
  skipped content (17,732 of 225,451 characters on the boosted Intake tab) and print laid out less: the page's tests and
  the folding design rely on `innerText`. Not kept.
- Measuring a drawing in a folded kept section by unfolding it inside `widthOf` (one section at a time): correct but
  Mufflers 35 → 45 ms; replaced by opening those sections once before the render draws.
- `<details>` written afresh every time: patched in place instead (they carry their state in the `open` attribute,
  which the observer sees when a user toggles it); a little faster.
- Patching inputs and text areas in place (resetting value and checked as a parse would): about 5 ms on Intake and
  Mufflers in a trial, not kept: some code after a render sets a field only when it is not focused (the Engine
  Simulator length) or keeps `_b` on the element, so a kept field would differ from a new one in ways the guard
  could miss.
- Section-level string equality (keep a section whose HTML is unchanged, replace the rest): replacing one small
  section still cost 7 to 10 ms of layout on the boosted Intake tab, and few of its sections stay the same, so the
  node-level patch was taken.
- Deferring far sections (the intercooler and turbo option tables) to idle with an updating mark: not done; it would
  change what the tests' settle waits for and show marks while typing.
- Caching drawing widths across renders: not done (pass three tried it; it only moves the same layout).

## What remains slow, and why

- **Boosted Intake, 57 to 70 ms here** (−31 to −42 %, the goal was −50 %): the layout of what really changed (about 80 %
  of its 3,725 texts change with the power, most of them in the 96-row intercooler table and the turbo tables) about
  16 ms; parsing its 329 KB of HTML 5 to 7 ms and the patch 6 to 8 ms; the boosted sections' own working about 16 ms
  (the exhaust march with its skin temperatures, the turbo and placement sections); the display passes 5 ms; the
  off-tab Headers result 3 ms. Getting to half would take skipping the parse of unchanged sections (the render would
  have to hand its HTML over in sections), the display passes limited to changed sections, or the option tables
  updated after the keystroke.
- **Hangers, about 84 ms**: still the isolator search (about 60 ms): up to 31 rebuilds of the part per isolator too
  hot at this reach, each with an 80-step fillet search of 41 points (cosines and sines). The bisection's 30 steps and
  the fillet search's steps are what the result is, so they were kept.
- The off-tab producers (Headers, Crossover, Intake) still work their results out on every input on every tab (3 to 9
  ms): proving which inputs each reads would need a dependency map the page does not have.
- At 4× throttling (a slower PC) the boosted Intake edit is still about 250 ms and Hangers about 360 ms.
